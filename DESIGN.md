# edi-mcp — design

Status: **scaffold, 2026-10-17.** Target: MCP **2026-07-28** (stateless core) on the
Python `mcp` SDK 2.x (`mcp>=2.0,<3`), Python 3.11+. Repo
`https://github.com/idss-mesa/edi-mcp`, package `edi_mcp`, console script `edi-mcp`,
tool prefix `edi_`, MIT (Regents of UNM). Template: `idss-mesa/neon-mcp` at `main`
(a5949d2); its D-register applies wherever this file is silent.

## Decisions register

| # | Question | Decision | Why |
|---|---|---|---|
| D1 | Upstream backend | **Hybrid.** `PastaBackend` when `EDI_API_KEY` is configured, `DataOneBackend` otherwise. Both implement one `Backend` protocol and are normalized into one output model per tool; `source.backend` names the one used. | PASTA has been auth-only since 2026-07-30; DataONE still serves EDI anonymously. |
| D2 | Bad key | PASTA 401 with a key → `upstream_forbidden` error; a credentialed 403 is an access-restricted package → `upstream_forbidden` with `reason: access_restricted` (2026-10-18). Never fall back to DataONE silently. | A silent downgrade hides misconfiguration and changes result semantics. |
| D3 | PASTA-only tools without a key | `edi_get_lineage`, `edi_recent_changes`, `edi_get_read_counts`, `edi_download_package` return `auth_required` with a hint to `edi://guide/api-key` (the registry fails fast, before any request). `edi_list_scopes` falls back to a static snapshot. `edi_get_quality_report` was on this list until 2026-10-19 (D18). | No DataONE equivalent. |
| D4 | Credential form | **Cookie primary, `?key=` fallback** (Step 1 probe, 2026-10-17: both return 200 on all 15 read methods tested). Exchange the key → `edi-token` (`POST auth.edirepository.org/auth/v1/key`), hold it in memory only, refresh with `/auth/v1/token/refresh` when < 1 h of the 8 h lifetime remains, and re-exchange once on a 401 from PASTA. Send it as `Cookie: edi-token=…` to PASTA hosts only. If the auth service is unreachable, use `?key=`, and `scrub_url()` every surfaced URL. | Keeps the long-lived key out of URLs, logs and cache keys while staying available if the IAM service is down. |
| D5 | Key config | `EDI_API_KEY` (env only), overridden by `EDI_MCP_EDI__API_KEY`; other names (`EDI_TOKEN`, `EDI_KEY`) are ignored with a warning; no flag; no `.env` autoload. | neon-mcp D18 pattern. |
| D6 | HTTP per-caller key | `X-EDI-Key` header, honoured only when `server.public_base_url` is https (or `allow_insecure_header_key`). Operator key not shared over HTTP by default. MCP bearer never forwarded. | neon-mcp D10 pattern; spec forbids token passthrough. |
| D7 | Write scope | Read-only v1. `edi_evaluate_package` (dry run) is a later opt-in. | User decision 2026-10-17. |
| D8 | XML safety | defusedxml for EML, Solr XML, resource maps and reports. EML is projected to a compact model **before** `fit_to_budget`; raw EML only via `edi://packages/{packageId}/eml`. | EML is untrusted and can be megabytes. |
| D9 | Identifier input | One resolver accepts `scope.id.rev`, `scope/id/rev`, `scope.id` + `revision=newest\|oldest`, `doi:10.6073/pasta/<md5>` / doi.org URLs, portal `mapbrowse` URLs and PASTA URLs; echoes `packageId` in `resolved`. Scope names fuzzy-resolve (neon resolve thresholds) against the dated `scopes.json` snapshot: exact scope, then a three-letter LTER site code (`cap` is always `knb-lter-cap`), then names, aliases and locations scored alike (so a shared location such as `Alaska` is `ambiguous_input`); an unknown well-formed code passes through for the backend to judge. | Agents paste whatever they found. |
| D10 | Downloads | `edi_download_entities` (batch, with the EML as `<packageId>.xml`) and `edi_download_package` (zip, key only): stdio only, `readOnlyHint=false`, `destructiveHint=false`. The plan is checked against file and byte caps before any transfer (the zip also against its `Content-Length`, and every stream against the cap). Files go to `<dir>/[dest_subdir/]<packageId>/<name>`, names sanitised to `[A-Za-z0-9._-]` with the mapping in `notes`; they stream to `.part` with a SHA-1 and move into place with an exclusive link, so **nothing is ever overwritten**: an identical file is `skipped`, a different one is a `conflict`. Expected SHA-1s come from PASTA's `/data/checksum` or GMN's `DataONE-Checksum` header; a mismatch removes the file. Redirect hops must stay on `downloads.allowed_hosts`. | neon-mcp D3; the 2026-07-28 annotations promise no destructive writes. |
| D12 | DataONE revisions | Parse the revision from the Solr `id` (a PASTA metadata URL, or a legacy `scope.id.rev` registered by the old LTER node); never follow `obsoletes`/`obsoletedBy` (missing on some superseded revisions, malformed on others). Search and listings de-duplicate per `scope.identifier`, keeping the highest revision; `numFound` is reported as an upper bound. | Verified 2026-10-17 on knb-lter-hbr.14 and knb-lter-jrn.210548103. |
| D13 | Fixtures | Recorded live through the real backends by `scripts/record_fixtures.py`; auth traffic and response headers are never stored; bodies are scrubbed (key, tokens, JWT shapes, token identity claims) before writing; a second pass re-scrubs earlier files; `check` gates promotion and runs in CI. Tests replay them through `FixtureRouter`, which enforces PASTA's credential rules and fails on credentials sent to any other host. | The Step 1 probe leaked a token prefix by truncating before scrubbing. |
| D14 | Search filters | `edi_search_packages` maps one set of filters onto both backends: free text (edismax), scope, creator last name (PASTA `author`, DataONE `investigatorText`; both case-insensitive), temporal overlap, bounding box (validated: no antimeridian crossing, because DataONE's bound-coordinate query cannot express it) and sort by publication date. The three bulk scopes are excluded unless asked for. DataONE pages advance by rows requested, not hits kept, because de-duplication shrinks a page. DataONE sorts by `dateUploaded` since its `pubDate` became unsortable (2026-10-19). | Verified 2026-10-18 (RESEARCH.md section 5); PASTA ignores the space-separated sort form, so live tests assert order, not just success. |
| D15 | EML projection | Each package tool fetches the EML once and parses it once; `projections/eml.py` turns it into compact models. Prose keeps inline markup (`itertext`), is cut at `max_text_chars`, and every list (people, coverages, taxa, keywords, entities, attributes, codes) is capped at projection time with a `…Total`, because the registry trims only one list. `<references>` resolve through one id map with a depth and cycle guard; a role beside a reference wins. EML sizes count only in bytes; PASTA's `/data/size` is authoritative. Backend entities pair with EML entities by id, then exact name, and leftovers are reported in `notes`. Raw EML is never inline (step 7 resource template). | `knb-lter-mcr.6.65` is 3.4 MB with 1 144 taxa (RESEARCH.md section 6). |
| D16 | Anonymous data URLs | `edi_list_entities` gives `dataUrl` (PASTA, needs a key) and `anonymousUrl` (the entity on its DataONE member node), which both member nodes serve without credentials; omitted for scopes the snapshot marks unreplicated. `edi_get_package` and `edi_get_metadata` have no paging, so when their entity list is cut the next step points to `edi_list_entities(offset=…)` (`budget_next_step`), and on DataONE `newestRevision` is qualified as DataONE's newest. | Verified 2026-10-19 on both nodes; the CN does not serve data entities. |
| D17 | Previews | `edi_preview_entity` streams the entity (PASTA with the key, the GMN member node without) and stops after `rows` records or `limits.preview_max_bytes`, because GMN ignores `Range`; streams are never cached. The EML gives the field delimiter, quote character and header lines; escape text and words (`\t`, `tab`, `#x09`, the literal `\r\n`) are unescaped; when the header count is missing the first record is a header if it names at least half the EML attributes, else per `csv.Sniffer`. A record cut by the early stop is dropped; NUL bytes mean binary and are refused. Cells are cut at 200 characters, rows at 100 columns. | RESEARCH.md sections 6 and 7. |
| D18 | Quality reports without a key | PASTA's quality reports are replicated to both GMN member nodes and served there anonymously, so `edi_get_quality_report` works on both backends (not in D3's key-only list); scopes the snapshot marks unreplicated still need a key. Reports are projected to counts by status plus the non-valid checks (errors first, capped at 50, with a total). | Verified 2026-10-19 on `gmn.lternet.edu` and `gmn.edirepository.org` (RESEARCH.md section 7). |
| D19 | Other users in feeds | PASTA's change feed names each uploader's `EDI-<hex>` principal; edi-mcp never keeps it, and the fixture scrubber replaces any `EDI-<40 hex>` and `check` fails on one. Citations come from the anonymous citation service; its HTML 400 for missing or restricted packages becomes `not_found`. | Privacy; the scrubber previously knew only the recorder's own principals. |
| D20 | tools/list size | **Output** schemas fold pydantic's `anyOf: [T, null]` into `type: [T, "null"]` (same meaning) and drop `default: null`, which keeps the 16 tools at 58.0 KB under the unchanged 60 KB bound. Input schemas are left as pydantic emits them, because some function-calling stacks handle `anyOf` better than type arrays. | Without it the list was 64 KB. |
| D11 | Registry | Ship `server.json` (`io.github.idss-mesa/edi-mcp`, PyPI `edi-mcp`, `EDI_API_KEY` optional secret). | None of the sibling servers has one. |
